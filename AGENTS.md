# Working with Luach as an AI agent

Luach is a Kotlin Multiplatform library for the Hebrew calendar and the times of the halachic day (zmanim): `HebrewDate` and `HebrewDay` (dates, holidays, the parsha, the omer, Daf Yomi), `Zmanim` (the halachic day of a `Location` on a date), `SolarDay` and two `SolarModel`s underneath it, `TefillahRules` and `LuachFormatter`. One Gradle module, `src/commonMain` only, package `com.eskotech.luach`, published as `com.eskotech:luach` under GPL-3.0-only with an App Store permission. The only dependency is `kotlinx-datetime`. Everything is computed from a date, a `Location` and the settings passed in: pure functions over values, with the same code on every target. `docs/` is the specification - `docs/README.md` is the index and every page cites the sources it describes; read the page for the area you touch before changing code.

## Project rules

1. **The license header is mandatory and exact.** Every code file (`.kt`, `.kts`, `.py`, `.yml`) starts with the same GPL block; copy it verbatim from any source file. The copyright line is `Copyright (C) 2026 Esko Tech Inc.`. `LICENSE` is the verbatim GPL-3.0 text and `ADDITIONAL-PERMISSIONS.md` the App Store permission.
2. **Code files are pure code below the header.** Names carry the meaning and `docs/` carries the explanation; that is where a reader looks for the reasoning, including in `docs/generate.py` and the workflows.
3. **Identifiers use the halachic term in Ashkenazi transliteration:** `isErevYomTov`, `asurBemelacha`, `mukefChoma`, `hadlakasNeiros`, `shaahZmanis`, `sefirasHaomer`. Enum entries follow the spelling already used in their enum (`Parsha` is `BERESHIT`, `SHEMOT`, `MATOT`; holidays, tractates and zmanim are `SHAVUOS`, `KESUBOS`, `TZAIS`). User-facing spellings live in `Transliterations`.
4. **The version is set in `build.gradle.kts` and mirrored in three places:** `Luach.VERSION` (`VersionTest` compares it with the Gradle version on every `jvmTest` run) and the installation snippets in `README.md` and `docs/publishing/README.md`. Bumping it is the owner's release decision.
5. Commit messages follow `type(scope): short description` (`fix(zmanim): ...`, `test(calendar): ...`, `docs: ...`); the scope is optional, and the docs workflow's own commits are `docs: ...`.

## Working agreement

- **Commit, push, tag or publish only when explicitly asked in the current request.** When you are authorized, doing so is fine and the responsibility lies with the requester. A `v*` tag is a release: `.github/workflows/release.yml` publishes to Maven Central without a confirmation step, and a published version is permanent. Pushed history stays as it is.
- **Credentials live outside the repository:** the five GitHub Actions secrets (`MAVEN_CENTRAL_USERNAME`, `MAVEN_CENTRAL_PASSWORD`, `SIGNING_KEY`, `SIGNING_KEY_ID`, `SIGNING_KEY_PASSWORD`), or a workstation's `~/.gradle/gradle.properties`. The build signs only when the Gradle property `signingInMemoryKey` is present, so a local build needs no key.
- **The CLA is implicit.** `CLA.md` is accepted by contributing; the last sentence of `.github/pull_request_template.md` says so, and that sentence is the whole mechanism.
- Update the `docs/` page that describes the code you changed in the same change (§Documentation); `README.md` and the other hand-written pages change when that is the task.
- A halachic rule you are not sure of is a question for a human: a wrong zman or a wrong tachanun flag reaches every user of the library. State the rule and its source in the pull request.

## Engineering rules

- **Every behavioral change ships with a test whose expected values are independent of the library:** a published table, a first-principles recomputation (the way `ReferenceCalendar`, `TefillahRulesTest` and `DafYomiTest` re-derive their answers), a golden time from an independent implementation, or a literal string. The snapshot tests prove that nothing changed unintentionally; the oracle tests prove the value is right.
- **`src/commonMain` and `src/commonTest` are common Kotlin over `kotlinx-datetime` and `kotlin-test`**, free of platform APIs, reflection, I/O, caches and global state. `commonTest` runs on Linux x64, macOS, the iOS simulator and Windows in CI; anything that needs the JDK (reflection, files, thread pools) belongs in `src/jvmTest`.
- **The API has one style:** opinions are values (`DayEdge`, `HalachicDay`, `Shitos`), closed sets are enums (`Holiday`, `Parsha`, `Zman`, the tractates), settings are data classes changed with `copy`, and a missing event is `null` (`Instant?`, `Duration?`) that propagates. Times are `kotlin.time.Instant` and `kotlin.time.Duration` (import `kotlin.time.Instant`); dates, weekdays and zones are `kotlinx.datetime` types.
- **Public API changes are deliberate.** `./gradlew apiCheck` compares the compiled JVM API with `api/luach.api`; after an intended change run `./gradlew apiDump`, commit the dump with the code and say in the pull request what changed. A binary-incompatible change (a removed or re-typed member, a changed default) is a major-version event for the owner to decide.
- Small single-purpose members: a new rule becomes its own named member with its own test.

## Architecture & the danger zones

### Source layout

| Package | Files | Role |
| --- | --- | --- |
| `com.eskotech.luach` | `Luach.kt` | The version constant. |
| `geo` | `Location.kt` | A validated latitude, longitude, elevation and `TimeZone` with the `inIsrael` and `mukefChoma` flags; coordinates from degrees-minutes-seconds; `Geodesic` and `RhumbLine`. |
| `solar` | `SolarModel.kt`, `NoaaSolarModel.kt`, `AlmanacSolarModel.kt`, `SolarDay.kt` | The models return UTC hours for a zenith angle; `SolarDay` places them on the requested civil day as `Instant`s. |
| `zmanim` | `DayEdge.kt`, `Zman.kt`, `Zmanim.kt` | `DayEdge` and `HalachicDay` describe a day; `Zmanim` turns them into times; `Zman` and `Shitos` are the standard list. |
| `calendar` | `HebrewMonth.kt`, `HebrewDate.kt`, `Molad.kt`, `Holiday.kt`, `Parsha.kt`, `HebrewDay.kt`, `DafYomi.kt`, `Tefillah.kt` | Date arithmetic and the year rules; the molad; the holiday of a day and its views; the parsha schedule; Daf Yomi; which prayers are said. |
| `format` | `LuachFormatter.kt` | Hebrew and transliterated names, Hebrew numerals, times of day; `Transliterations` holds the replaceable defaults. |

Dependencies point one way: `format` → `calendar` + `zmanim` → `solar` → `geo`. `calendar` knows nothing about the sun; `Zmanim.hebrewDay` is the bridge, and it passes the location's flags.

### The solar day (`solar/` - where times go wrong)

- **A model returns a UTC hour, `SolarDay` does every placement.** `SolarModel.sunrise/sunset/solarNoon` give an hour in `[0, 24)` of a UTC date (or null) for a latitude, a longitude and a zenith. `SolarDay` picks the UTC date whose mean solar noon is nearest the civil noon (`localNoon` = the start of the day in the zone plus 12 h, so a date on which the clock skips an hour still works; the UTC date is that of `localNoon + longitude × 4 min`), then moves the returned hour by a whole day if that brings it closer to the event's reference point: mean solar noon (12:00 UTC − longitude × 4 min on that UTC date) for the noons, six hours before it for a rising event, six hours after it for a setting event. So the events of a civil day bracket one solar noon even when the zone and the longitude disagree by half a day, and Apia (UTC+13/+14, a day ahead of the sun), Kiritimati (UTC+14), Baker Island (UTC−12) and a 00:30 summer sunset land on the requested day. `SolarDayTest`'s date-line and zone-mismatch cases (Samoa 2011-12-31, Kiritimati 1995-01-01, 180° in the UTC zone) and the Rapa Iti / Anadyr snapshot ranges guard it.
- **Depression `0.0` is the apparent event.** It uses `ApparentHorizon.zenith(elevation)` = 90° + refraction (34′) + solar radius (16′) + the dip of the horizon from the elevation (`acos(R / (R + elevation / 1000))`, R = 6356.9 km). Every other depression is geometric: refraction, radius and `atElevation` play no part. So `sunrise`/`sunset` are elevation-adjusted, `seaLevelSunrise`/`seaLevelSunset` are at sea level, and `sunriseAt(16.1)` is the same at any elevation.
- **`meanSolarNoon` (= `Zmanim.fixedLocalChatzos`) is always present** and independent of the zone's offset and daylight saving: 12:00 UTC − longitude × 4 min on the chosen UTC date. `NoaaSolarModel.solarNoon` is always present; `AlmanacSolarModel`'s noon is the midpoint of its sunrise and sunset and null when they are.
- **Null means "the sun does not get there today"** (polar day or night, a 26° dawn in June at 70°N); `temporalHour` is null when either sea-level event is, and everything downstream stays null (`ZmanimTest.polarDayAndNightGiveNullEverywhere`).
- `depressionBeforeSunrise` / `depressionAfterSunset` bisect the geometric depression (60 steps, from the apparent horizon's 0.833° up to 90° for a positive offset, from −90° up to it for a negative one) and return a geometric depression for `sunriseAt`/`sunsetAt`, or null when the sea-level event is missing or the sun stays short of that depth; `SolarDayTest.depressionSearchRoundTrips` pins the round trip within a second.
- **The two models are stateless objects** that agree within two minutes away from the poles (`SolarModelTest.modelsAgreeWithEachOtherAwayFromThePoles`) and each matches its ~300-row reference table to 1e-7 hours (`modelsMatchIndependentReference`). A change that moves those numbers comes with a new reference from an independent implementation. `NoaaSolarModel` is the default everywhere; a third model implements `SolarModel` and brings its own reference table. `elevation` and `azimuth` evaluate the position at the exact UTC instant, date and time of day together.
- Every property recomputes from scratch; a caller that needs a value twice holds it.

### Zmanim (`zmanim/` - the opinion is a value)

- **Four kinds of zman, one member each:** an edge (`alos(edge)`, `tzais(edge)` for a `DayEdge`), a fraction of a day (`hourOfDay(hours, day)` = `alos + hours × (tzais − alos) / 12` for a `HalachicDay`; the named fractions sof zman shema 3, sof zman tefillah and achilas chametz 4, biur chametz 5, mincha gedola 6.5, samuch le mincha ketana 9, mincha ketana 9.5, plag 10.75 all take a `HalachicDay` defaulting to `GRA`), a time of the solar day (`chatzos`, `fixedLocalChatzos`, `chatzosHalaylah`, `hadlakasNeiros`), and a molad-based time. A new opinion is a constant on `DayEdge` or `HalachicDay`, a `Shitos`, or a row in the cookbook of `docs/zmanim/README.md`; the members stay as they are.
- **`alos(edge)` and `tzais(edge)` are exhaustive `when`s over the sealed `DayEdge`** (`Horizon`, `Depression`, `Minutes`, `ProportionalMinutes`, `Shifted`, `DawnInterval`). A new edge kind touches: the subtype in `DayEdge.kt`, both `when`s, the edges table in `docs/zmanim/README.md`, `ZmanimCatalogue.EDGES` in `SnapshotFixtures.kt` (so the sweep covers it) and a definition-based test in `ZmanimTest`.
- `useElevation` switches `hanetz`/`shkiah` (and everything measured from them) between the elevation-adjusted and the sea-level events; depression edges are independent of it. `hadlakasNeirosMinutes` (18) is subtracted from `shkiah`.
- **`Zman` is the standard list in the order of the day and `Shitos` the four opinions it is computed with** (alos edge, misheyakir edge, `HalachicDay`, tzais edge; `Shitos.GRA` is the default, `Shitos.MAGEN_AVRAHAM` is 72 minutes throughout). `zman(zman, shitos)` returns exactly what the corresponding member returns, and `all()` stays in enum order with nulls kept (`ZmanimTest` checks the list against the members). A new `Zman` entry comes with its `zman()` branch, a `Transliterations.ZMANIM` name and the Hebrew name in the formatter, and new snapshot counts.
- **The molad-based zmanim are clipped to the civil day** (local midnight to local midnight): `molad`, `kiddushLevanaStart(rule, alos, tzais)` and `kiddushLevanaEnd(rule, alos, tzais)` look at the previous, current and next month's `Molad` and return the value that falls today, else null; a daytime start moves to `tzais` and a daytime end to `alos` when those are passed.
- `isAsurBemelacha(at, tzais)` reads `inIsrael` and `mukefChoma` from the `Location` through `hebrewDay`, so an Israeli location keeps its second days out of the check; it is false when `tzais` or `shkiah` is null.
- `Zmanim` is a data class of six settings (`location`, `date`, `model`, `horizon`, `useElevation`, `hadlakasNeirosMinutes`). A new setting is a constructor parameter with a default, mirrored in `Zmanim.today(...)`, with its getter listed in `Getters.CONFIGURATION` in `SnapshotFixtures.kt` so the reflection sweep treats it as a setting.

### The Hebrew calendar (`calendar/HebrewDate.kt`, `Molad.kt`, `HebrewMonth.kt`)

- **A `HebrewDate` is its `epochDay`** (the same count as `LocalDate.toEpochDays()`): `equals`, `compareTo` and `hashCode` use it. The earliest day is 1 Tishrei of the year 1 (epoch day −2092590); `of` throws `IllegalArgumentException` for a year below 1, an `ADAR_II` in a common year or a day outside `1..monthLength`.
- **A date is the civil date.** `HebrewDate.from(instant, zone)` is the civil date in the zone; the halachic date after tzais is the caller's decision, made with `Zmanim`.
- **The year rules are the four postponements:** Rosh Hashanah is the day of the molad of Tishrei, delayed by a molad at or after 18 h, a Tuesday molad at or after 9 h 204 p in a common year, a Monday molad at or after 15 h 589 p in the year after a leap year, and off Sunday, Wednesday and Friday. `yearLength` is the difference of consecutive Rosh Hashanahs (353-355, 383-385), `YearType` is its last digit (3 deficient, 4 regular, 5 complete), and the month lengths follow from the type. `HebrewDateTest` converts every day of 5770-5791 both ways against a table of Rosh Hashanah dates (`ReferenceCalendar`) and recomputes every molad from the lunation count; a change here keeps that oracle.
- **`Molad`:** 29 d 12 h 793 p per lunation, 1080 parts an hour, 18 a minute. `date` is the civil `HebrewDate` (a molad at 6 h or later of its 18:00-based day belongs to the next civil date); `instant` is Jerusalem mean solar time (the stated clock time minus the Temple Mount longitude 35.2354° × 4 min, the chalakim as thirds of a second). The four kiddush levana instants are fixed offsets from it (+72 h, +168 h, +14 d 18 h 22 m 1.666 s, +360 h).
- Months are numbered from Nisan (`NISAN(1)` … `ELUL(6)`, `TISHREI(7)` … `ADAR(12)`, `ADAR_II(13)`) and a year starts with `TISHREI`; `plusMonths` walks Hebrew months (Elul to Tishrei, Adar or Adar II to Nisan) and clamps the day, `plusYears` maps `ADAR_II` to `ADAR` when the target year is common.

### HebrewDay: holidays, views and the parsha (`calendar/HebrewDay.kt`, `Holiday.kt`, `Parsha.kt`)

- **Exactly one `Holiday` per day or null**, from the month-by-month rule in `HebrewDay.holiday`; everything else is a boolean view. `inIsrael` decides the second days and Isru Chag; `mukefChoma` changes `isPurim` (and through it `alHanissim`). Rosh Chodesh is the view `isRoshChodesh`. Fasts move off Shabbos in `observedFast` and `purimMonth` (17 Tammuz, 9 Av and 3 Tishrei to Sunday, Taanis Esther to Thursday).
- **`isYomTov` is wide on purpose:** every holiday that is neither an eve, nor Isru Chag, nor a fast other than Yom Kippur - so Chol Hamoed, Chanukah, Purim, Lag BaOmer, Tu BiShvat, Pesach Sheni and Yom Kippur all count, and the tefillah rules depend on that width. `isYomTovAsurBemelacha`, `isTaanis` and the specific views answer the narrower questions.
- A new `Holiday` entry carries its `isTaanis` / `isErev` / `asurBemelacha` flags and comes with the rule in `HebrewDay.holiday`, a `Transliterations.HOLIDAYS` name and the Hebrew name in the formatter, the per-date rule in `HolidayTest`, its tefillah consequences in `TefillahRulesTest`, regenerated docs tables and regenerated snapshots.
- **The parsha schedule is count-based** (`TorahCycle.schedule` in `Parsha.kt`): the Shabbosos of a cycle - from the Shabbos after Simchas Torah, skipping the Shabbosos of Pesach, Shavuos, Rosh Hashanah, Yom Kippur, Sukkos and Shemini Atzeres - are counted, the 53 readings from Bereishis to Haazinu are assigned in order, and the doubles are combined as the counts require: Vayakhel-Pekudei when fewer than 25 Shabbosos precede Pesach, then Tazria-Metzora, Acharei Mos-Kedoshim and Behar-Bechukosai until 34 readings fit before Shavuos; Chukas-Balak outside Israel when the second day of Shavuos is Shabbos and Matos-Masei whenever a double is still needed before Shabbos Chazon; Nitzavim-Vayelech when one Shabbos with a reading remains between Rosh Hashanah and Simchas Torah. `ParshaTest` proves every cycle of 5700-5900, Israel and diaspora: every parsha once, in order, the Yom Tov Shabbosos without a reading, the anchored Shabbosos (Bereishis, Tzav/Metzora/Acharei Mos before Pesach, Bamidbar/Naso before Shavuos, Devarim before 9 Av, Nitzavim before Rosh Hashanah), the special Shabbosos and `upcomingParsha`.
- **`Parsha` order is load-bearing:** the 54 readings in Torah order (`VEZOT_HABERACHAH` last; it is read on Simchas Torah), then the seven doubles with `first`/`second`, then the special Shabbosos with `isSpecialShabbos`; `WEEKLY`, `DOUBLES` and `SPECIAL_SHABBOSOS` are filtered from `entries`. `parsha` is null on a weekday and on a Yom Tov Shabbos; `upcomingParsha` always has a value.
- `daysFromTekufasTishrei` counts whole days from the autumn tekufa of the 365.25-day year; `TefillahRules` starts vesein tal umatar outside Israel when it reaches 47 (Sunday when that day is Shabbos). `isBirkasHachamah` is a whole number of 28-year cycles (10227 days) from 2009-04-08.

### Daf Yomi (`calendar/DafYomi.kt`)

- **Bavli keeps two anchors and picks by date:** cycle 1 from 1923-09-11 (`BAVLI_FIRST_CYCLE`), 2702 days with 12 pages of Shekalim (2-13); from cycle 8, 1975-06-24 (`BAVLI_EIGHTH_CYCLE`), 2711 days with 21 pages (2-22). Kinnim, Tamid and Middos continue Meilah's numbering from 23, 26 and 34; every other tractate starts at 2. A date before 1923-09-11 throws.
- **Yerushalmi skips two fasts:** from 1980-02-02 (`YERUSHALMI_FIRST_CYCLE`), 1554 pages per cycle (`YerushalmiTractate.PAGES_PER_CYCLE`); Yom Kippur and the observed Tisha BeAv (Sunday 10 Av when 9 Av is Shabbos) return null and are left out of the count, so a cycle lasts 1554 days plus those fasts. A date before 1980-02-02 throws; a fast day before it still returns null.
- `DafYomiTest` re-derives both schedules from the cycle dates and the page counts for every day. A page count or an anchor is published Daf Yomi data; a change comes with a published source in the pull request.

### Tefillah rules (`calendar/Tefillah.kt`)

- **Every `TachanunCustoms` switch names a case where tachanun is omitted.** The defaults are a specific set of customs (`omitWeekAfterShavuos`, `omitPesachSheni` and `omitMinchaErevLagBaomer` true, the other nine false). A new custom is a new switch with a default; an existing default changes with the owner.
- `tachanunAtMincha` is "false on the day before a day without tachanun" with named exceptions (before Erev Rosh Hashanah, Erev Yom Kippur, Pesach Sheni and Lag BaOmer mincha keeps tachanun; the eve of Lag BaOmer drops it under its switch). An exception is a halachic decision.
- **`all(day)` returns a `TefillahSummary` with one field per rule, named exactly like the function**; `TefillahRulesTest.summaryMatchesTheIndividualRules` keeps them equal. A new rule is a function, a field, a line in that test, a row in `docs/tefillah/README.md` and a line in the sample's output.
- The rules derive from `HebrewDay` views (the width of `isYomTov` matters), `inIsrael` and `daysFromTekufasTishrei`; `TefillahRulesTest` re-derives every rule from the holiday table for every day of 5770-5790 and checks the published vesein tal umatar start dates.

### Formatting (`format/LuachFormatter.kt`)

- `LuachFormatter` is a data class of settings; `hebrew = true` uses the fixed Hebrew names in the file, transliterated output uses the replaceable maps whose defaults are `Transliterations` (one map per enum: months, weekdays, holidays, parshios, Bavli, Yerushalmi, zmanim). **Hebrew script lives in two places:** `LuachFormatter.kt` and the tractate `hebrewName`s in `DafYomi.kt`. A new enum entry anywhere gets both its Hebrew name and its transliteration; `LuachFormatterTest` pins every list.
- Hebrew numerals: `formatNumber` covers `0..9999` and throws outside; `quoteMarks` (geresh after one letter, gershayim before the last), `thousands` and `finalLetters` are the three switches; 15 and 16 are `טו` and `טז`.
- `formatTime` truncates and returns an empty string for a null instant; `twelveHourClock` and `amPmNames` are the clock settings. `formatOmer` renders day 33 in transliteration as the Lag BaOmer holiday name; `formatRoshChodesh` names the month that begins (on a 30th, the next month); `formatYearSignature` is the three-letter signature without marks.

### Locations (`geo/Location.kt`)

- Validation lives in the constructor and therefore in `copy`: latitude `-90..90`, longitude `-180..180`, elevation finite and at least 0; `NaN` fails every check. `Location.coordinate(degrees, minutes, seconds, direction)` is the degrees-minutes-seconds helper.
- `geodesicTo` is Vincenty's inverse on WGS84 (iterated to 1e-12, at most 20 iterations): coincident points give distance `0.0` with `NaN` bearings, non-convergence (nearly antipodal) gives all `NaN`. `rhumbLineTo` is spherical with R = 6378137 m. The time zone and elevation play no part. `LocationTest` holds hand-computed references.
- `inIsrael` and `mukefChoma` travel on the `Location` so a place is described once; `Zmanim.hebrewDay` and `isAsurBemelacha` read them.

### Tests: the oracle layer and the snapshot layer

- **Oracle tests (`src/commonTest`)** prove the right value against expectations independent of the library: `HebrewDateTest` (the Rosh Hashanah table and the month rules), `HolidayTest` (rules written out per date), `ParshaTest` (cycle invariants), `DafYomiTest` (cycle arithmetic), `TefillahRulesTest` (re-derived from the holiday table), `LuachFormatterTest` (literal strings), `ZmanimTest` (golden times for Lakewood on 2017-10-17 from an independent implementation, plus every edge and fraction recomputed from its definition), `SolarModelTest` (the ~300-row reference table), `SolarDayTest` (twilight golden values, date-line placement), `LocationTest`. `Mismatches` collects a sweep's failures and reports the count with the first 25 messages (`assertNone(label)`), so one run shows every mismatch; `assertInstant` / `assertDuration` compare within `MILLISECOND_TOLERANCE` (2 ms) or `TEMPORAL_HOUR_TOLERANCE` (15 ms), and those two values are the tolerances.
- **`Places` holds the fixed test locations.** Their coordinates are the inputs the solar reference table and the golden zmanim were computed for, so a coordinate change comes with new tables.
- **`VersionTest` (`src/jvmTest`)** compares `Luach.VERSION` with the `luach.version` system property that the `jvmTest` task sets from the Gradle version; `LuachSmokeTest` checks the constant's `major.minor.patch` shape on every target.
- **Snapshot tests (`src/jvmTest`)** prove nothing changed unintentionally: `Snapshot.kt` records every value under a member name and a group and folds them into three fingerprints per key - the count, an exact hash (instants and durations at millisecond precision, so a last-bit floating-point difference between CPU architectures leaves it unchanged; doubles exact) and a coarse hash (instants to the second, doubles to six significant digits). The stored files in `src/jvmTest/resources/snapshots` carry an `environment` line; on the same JVM the exact hash must match, on another JVM the coarse hash is enough.
- **`Getters.zeroArg` (`SnapshotFixtures.kt`) discovers public zero-argument getters by reflection**, so a new public getter on `SolarDay`, `Zmanim`, `HebrewDate` or `HebrewDay` changes the snapshot counts by itself. The procedure for an intended change: `./gradlew jvmTest -PupdateSnapshots`, review the diff (a changed count means members appeared or disappeared; a changed hash with the same count means values changed; the failure message names the members and the places or date ranges), and explain the diff in the pull request. Snapshot files are only ever regenerated, and an unexplained snapshot change is a bug.
- `SnapshotFixtures.kt` is the catalogue the sweeps iterate: `SamplePlaces` (twenty places including the date-line and daylight-saving cases), `SampleDates`, `ZmanimConfig`, `ZmanimCatalogue` (every edge, day, preset and hour grid). Extend the catalogue when you add an edge, a day or a setting; the sweeps protect what the catalogue reaches.
- `commonTest` compiles and passes on Kotlin/Native, so it uses common Kotlin and `kotlin-test` APIs only. Run `./gradlew linuxX64Test` locally after touching it; CI runs the other hosts.

## Documentation

- **Two kinds of documents, and the generator decides which is which** (`docs/README.md`). Generated, overwritten on every run: `docs/reference/kotlin-files.md`, `docs/reference/non-kotlin-files.md`, `docs/reference/public-api.md`, `docs/build-release.md`, and every region between a `generated:NAME` / `/generated:NAME` HTML-comment marker pair inside the hand-maintained pages (the file inventory of `repository-map.md`, the solar constants, the zmanim member tables, the month, holiday and parsha tables, the formatter settings, the tractate tables, the tachanun customs, the test and snapshot inventories). To change a generated table, change `REGION_DOCS` / `GENERATED_FILES` in `docs/generate.py`.
- **Hand-maintained: everything else**, updated with the code: the top of `repository-map.md`, the per-area pages (`geo`, `solar`, `zmanim`, `calendar`, `formatting`, `daf_yomi`, `tefillah`, `testing`, `publishing`), `README.md`, `CONTRIBUTING.md` and this file. The pull request template asks whether the page describing the changed code was updated.
- Run `python3 docs/generate.py` from the repository root before committing. It rewrites a file only when its content changes and re-runs itself until the output is stable, so one invocation is idempotent; `.github/workflows/docs-regenerate.yml` reruns it on every push to `main` and commits the difference, and a clean local run keeps that commit a no-op.
- The docs describe the computations, their inputs and their edge cases, and cite the source files.

## Verifying your changes

- **Minimum before a pull request:** `./gradlew jvmTest apiCheck`, then `python3 docs/generate.py` and commit whatever it regenerated.
- **`src/commonMain` or `src/commonTest` changed:** also `./gradlew linuxX64Test` (Kotlin/Native compiles and rounds differently; CI adds macOS, the iOS simulator and Windows).
- **A result changed on purpose:** regenerate the snapshots with `./gradlew jvmTest -PupdateSnapshots`, read the diff, and explain it in the pull request together with the halachic or astronomical source.
- **The public API changed on purpose:** `./gradlew apiDump`, commit `api/luach.api`, state the change.
- **A new file:** the license header at the top, pure code below it, names per §Project rules, and the `docs/` page that describes it.
- **A new or changed zman, holiday, rule or name:** the Hebrew name and the transliteration, the oracle test, the catalogue entry in `SnapshotFixtures.kt`, the docs row, and `./gradlew :sample:run` still prints a sensible luach.
