# Luach repository documentation

Every fact here is derived from the project files (Kotlin sources, Gradle scripts, GitHub workflows and the test resources). The library reads no runtime data: everything it returns is computed from a date, a `Location` and the settings passed in, so these pages describe the computations, their inputs and their edge cases.

Two kinds of documents live here:

- **Generated by `docs/generate.py`** (regenerated on every push to the default branch by `.github/workflows/docs-regenerate.yml`): `reference/kotlin-files.md`, `reference/non-kotlin-files.md`, `reference/public-api.md`, `build-release.md`, and every region between a `generated:NAME` / `/generated:NAME` HTML-comment marker pair in the hand-maintained pages (the file inventory of `repository-map.md`, the constants of `solar/README.md`, the member tables of `zmanim/README.md`, the month, holiday and parsha tables of `calendar/README.md`, the formatter settings, the tractate tables, the tachanun customs, and the test and snapshot inventories in `testing/README.md`). To change one of those tables, change the generator (`REGION_DOCS` and `GENERATED_FILES` in `docs/generate.py`).
- **Hand-maintained**: everything else - the top of `repository-map.md` and the per-area pages, which are prose that cites the source files. Update the relevant page when you change the code it describes.

Run the generator from the repository root with `python3 docs/generate.py`. It needs only the standard library plus PyYAML for the workflow tables of `build-release.md` (without PyYAML that section is skipped with a note). It rewrites a file only when its content changes and re-runs itself until the output is stable, so one invocation is idempotent.
